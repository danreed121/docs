Store new content or update existing content in the repository.

## Endpoints

### POST — New Content

Create new content where the `XmsContentId` is generated by the system, or update content where identification is handled by extraction.

```
POST repo
POST repo/tag/{tagName}
```

### PATCH — Existing Content

Update content identified by `XmsContentId`.

```
PATCH repo/xmsId/{xmsId}
PATCH repo/xmsId/{xmsId}/tag/{tagName}
```

## Path Parameters

| Parameter | Description |
|-----------|-------------|
| `{xmsId}` | The `XmsContentId` of the destination content to update |
| `{tagName}` | Optional. Tag for the new Content Instance. Defaults to `HEAD` if omitted |

See [Path Parameters](/api/parameters/path) for details.

## Parameters

All [common parameters](/api/parameters/form) apply. Additionally:

- [Property Parameters](/api/parameters/property) (`prop.[name]`) are used to assign values to properties on the content
- [File Input Parameters](/api/parameters/file-input) can provide content as file attachments
- [Transform Parameters](/api/parameters/transform) are passed to the transform if a `pubType` is specified

## Behavior

- **POST without `xmsId`**: The system generates a new `XmsContentId`, or uses extraction and identification facilities to locate existing content (e.g., when XML content contains the identifying property).
- **PATCH with `xmsId`**: Updates the specified Content Entity directly.
- When a `pubType` is specified, the content passes through the associated transform, enabling cascading operations.
- When no `pubType` is specified, `srcContentId` or `srcFile` provide the direct source for the load (no transform).
- `viewPath` is required when adding a new Content Entity.

## Query Parameters

All [query parameters](/api/parameters/query) apply: `view`, `dryRun`, `deepResults`, `summarize`.

## Response

Returns a `LoadResult` resource (XML or JSON based on `Accept` header), unless the `view` query parameter is set, in which case the transform result is returned directly.
